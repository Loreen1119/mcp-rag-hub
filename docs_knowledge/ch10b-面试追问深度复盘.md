# 第 10B 章：面试追问深度复盘

> 进阶追问 —— 面试官在基础问题之后，考察工程权衡和第一性原理思考能力的深度问题。

---

## 追问 1：CE 延迟优化（92% → 砍半）

### 问题

> Cross-Encoder 精排把语义盲区的 MRR 从 0 救回 1.0，但它占了总延迟的 92%。在不牺牲太多召回精度的前提下，把延迟至少砍掉一半，你会从哪些方向优化？

### 答题框架：先亮公式，再三条线展开

```
CE 总延迟 = 单次推理延迟 × 候选数量
```

所有优化方案，要么砍左边，要么砍右边，要么并行重叠。

### 方向一：减少候选数量（砍右边）— P0 优先

| 方案 | 思路 | 效果 |
|------|------|------|
| 固定 top-K 截断 | RRF 后直接取前 20 | 候选从 40→20，延迟直接减半，零风险 |
| **自适应截断** | 根据 RRF 分数分布形状动态决定 K | 好查询截到 5 个，模糊查询保留全部 |
| 置信度门控 | RRF top-1 分数远超后续 → 直接跳过 CE | 高置信场景零 CE 成本 |

**自适应截断的核心思路**（不叫"梯度截断"，应叫"基于 RRF 分数形态的自适应截断"）：

固定截断用**位置**做决策——不管分数分布长什么样，统一取前 N 个。如果真答案恰好排在第 N+1 位，CE 再强也无能为力。

自适应截断用**信号的形状**做决策：
- 检测 RRF 分数序列的衰减模式。如果第 5 位后出现断崖式下跌（相邻分数衰减率 > 阈值），说明后面全是噪声，在断崖处熔断
- 如果分数一路平缓下降，说明这是长尾模糊查询，真答案可能藏得很深，不截断，让 CE 全力精排
- 最小保留 5 个，最大保留原始候选数

判定函数示例：
```
衰减率 = (score_i - score_{i+1}) / score_i
当衰减率首次超过 0.3 时截断，最小保留 5
```

**面试时需准备好**：阈值怎么定（离线验证集扫出来的）、如何验证（画截断位置 vs MRR tradeoff 曲线）、线上分布漂移后怎么兜底（回退到固定 top-K）。

### 方向二：降低单次推理延迟（砍左边）— P1

| 方案 | 思路 | 延迟削减 | 代价 |
|------|------|----------|------|
| INT8 量化 + ONNX Runtime | 模型压缩 | ~20-35% | 需校准数据集，可能微掉点 |
| 换轻量 CE（MiniLM 6 层） | 更小的模型 | ~50% | 精度需验证 |
| 知识蒸馏 | 大 CE 教小 CE | ~50% | 训练成本高 |

### 方向三：并行 / 流水线 — P2

| 方案 | 思路 |
|------|------|
| CE 与 LLM 生成并行 | RRF 出结果后，一边跑 CE 精排，一边用未精排的 top-N 构建 prompt 预填充 KV cache。CE 结果出来后如果 top-1 一致直接生成，不一致才重排 |
| Batch CE | 多个 query 的候选合并成 batch 一次推理，利用 GPU 并行度 |

### 回答收尾：优先级和风险

> P0（砍候选）+ P1（量化）组合已经稳超 50%。自适应截断的阈值需要用生产数据持续校准，如果分布漂移导致截断率异常，策略是回退到固定 top-K，保证 SLA 兜底。

## 追问 2：Bi-Encoder 二次过滤为什么是错的

### 问题

> 在 RRF 之后、CE 之前，能不能用 Bi-Encoder 的余弦相似度阈值再做一次过滤，减少 CE 候选量？

### 答案：不行，这会破坏双路召回互补的前提假设。

**BM25 存在的价值**恰恰是补充向量检索（Bi-Encoder）的语义盲区——专有名词、型号、代码片段等字面匹配强的内容，在 Bi-Encoder 眼里相似度天然偏低。

用 Bi-Encoder 做阈值过滤，等于**用向量检索的偏见去否决 BM25 的贡献**——那些 BM25 辛辛苦苦捞上来、向量检索天然打低分的专有名词相关候选，会被 Bi-Encoder 阈值直接过滤掉。

结果：双路召回 → 又变回单路召回的瓶颈，而且多了一次模型推理，延迟不降反升，架构复杂度白增加。

**核心教训**：优化方案不能破坏上游模块存在的前提假设。引入任何一个新模块之前，先问"它会不会否定我前面某个模块存在的原因"。

### 正确替代方案

直接基于 RRF 分数本身做截断，而不是引入一个新的评分模型。RRF 已经融合了两路的排名信息，不需要再让 Bi-Encoder 来"二次评判"。

## 追问 3：RRF 的 k 值怎么定

### 问题

> 经典默认 k=60，你是怎么定义这个值的？

### 答案结构：k 在做什么 → 60 从哪来 → 怎么正确推导

**第一步：k 控制的是排名曲线的"陡峭度"**

$$RRF(d) = \sum_{i} \frac{1}{k + rank_i(d)}$$

| k 值 | rank=1 权重 | rank=N 权重 | 效果 |
|------|-----------|------------|------|
| k→0 | 极大 | 极小 | 只有 top-1 说了算 |
| k→∞ | 均等 | 均等 | 排名信号完全抹平 |
| k=60 | 适中 | 适中 | 头部有优势但不独裁 |

**第二步：60 没有理论推导**

它是 Cormack 等人在 2009 年 TREC 数据集上网格搜索扫出来的经验值。换个数据集、换个候选规模，60 未必最优。

**第三步：正确的设置方式——k 与候选规模绑定**

先确定期望的权重比（rank=1 与 rank=N 的权重比 r），再反推 k：

$$k = \frac{N - r}{r - 1}$$

以本项目为例：
- RRF 输入候选池 N=40（BM25 top-20 + Vector top-20）
- 期望 rank=1 权重是 rank=40 的约 3 倍
- 代入：k = (40 - 3) / (3 - 1) = 18.5
- 在验证集上以 MRR 为目标扫 k ∈ [10, 50]，实验最优 k=30

**结论**：k 不是 magic number，是"你允许多少权重比"的数学表达。正确的做法是先定候选规模和期望权重比，反推 k 的范围，再在验证集上微调确认。盲目用 60，相当于假设你的候选分布和 2009 年的 TREC 数据一样。

**本项目实际数据**：参数消融实验中 RRF_K ∈ {30, 60, 120} 在小语料下全部 MRR=1.0，系统对 k 不敏感。最优配置选 k=30（配合 CE_TOP_K=3 实现最低延迟）。

## 追问 4：BM25 vs 向量，各自在什么情况下更强

### 分场景数据（来自 15 组 GoldenTestSet）

| 类别 | BM25 MRR | Vector MRR | Full Pipeline MRR |
|------|----------|------------|-------------------|
| exact_match（E01-E05） | 1.0 | 1.0 | 1.0 |
| mixed（M01-M05） | 0.9 | 0.9 | 1.0 |
| semantic（S01-S05） | **0.8** | **1.0** | **1.0** |

### BM25 的优势

专有名词和精确术语匹配。query 中的关键词在文档中原文出现时，BM25 精准命中。

### 向量检索的优势

自然语言语义查询。典型案例 S03——"怎么评价一个检索系统好不好？"——query 里没有一个词直接命中文档中关于 Ragas 评测框架的部分：
- BM25 MRR = **0.0**（完全失效，把一篇无关笔记排到第一位，得分 1.2）
- Vector MRR = **1.0**（通过语义理解准确命中评测章节）

### BM25 最致命的短板

不是精确匹配不强，而是**它会引入强噪声**。S03 中 BM25 给不相关 chunk 打了 1.2 分排第一，直接把 RRF 融合后 MRR 从 1.0 拖到 0.5。好在 CE 精排兜底，最终修正回 1.0。

### 怎么调两路权重

**答案：没有调，刻意不调。**

原因：BM25 原始分数范围 0~几十，向量余弦相似度 0~1，直接加权融合 BM25 会靠量纲优势主导排序——但这不代表 BM25 更"正确"，只是它的分数天生更大。

采用的方案是 **RRF 而非加权融合**：只用排名位置，不用原始分数，天然消除量纲差异。两路检索地位完全对等。这个设计的代价是当某一路排名完全错误时（如 S03 中的 BM25），会把 RRF 融合结果也拉低——这个代价由 CE 精排来承担。

**核心结论**：BM25 和向量检索的权不是"调"出来的，而是通过架构选择（RRF + CE）让它们各自在自己的优势区发挥作用，在弱势区由另一方兜底、最终由 CE 纠正。

## 追问 5：好的面试答案的共同结构

回顾所有追问，好的回答都有统一框架：

1. **先定义问题空间**（公式或前提假设）——CE 延迟 = 单次 × 候选数；RRF k 值 = 权重比的数学表达
2. **再按方向展开方案**——每个方向讲清做了什么、为什么、代价是什么
3. **最后点明风险和兜底策略**——分布漂移、回退机制

差的回答只是在罗列知识点。好的回答展示的是"遇到一个新问题时怎么建模"的判断力。

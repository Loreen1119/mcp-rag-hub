## 一、先说四条结论

1. **Hit@5 阶梯**：BM25 单路 **0.3045** → 向量单路 0.2627 → RRF 融合 **0.3254**（335 条有空 golden 样本口径）。简历占位符 **[X] = 0.3045**（BM25 无优化基线）、**[Y] = 0.3254**（RRF）。**注意：[Y] 相对 [X] 只提升 2.1 个百分点**，这是真实结果，原因已在第五节定位，不是跑错。
2. **CE 精排在本语料上对 Hit@5 无净增益**：同一 200 条子集上，RRF 0.31 → CE 0.31，命中集合变化为 **+18 新增 / −18 丢失（净 0）**。CE 的价值只体现在拒答门控与版本正确性（见第三、四条）。
3. **拒答阈值调优：默认阈值下"零误杀"是"从不拒答"的副作用**。`CE_THRESHOLD=0.3` 时正确拒答率只有 **2.5%（1/40）**，拒答机制形同虚设；因为 `bge-reranker-base` 的 top1 分数严重饱和（可答样本 **97.5% ≥ 0.99**），0.3~0.7 这段候选阈值**全部落在饱和区、无操作空间**。真正可调的是 0.97~1.00 的极窄带，膝点在 **0.98**：正确拒答率 2.5% → **25%**，误杀率 0% → 5%，净命中不降（62/200）。
4. **[Z] 版本混淆干扰率 0.3226 → 0.2581**（BM25 → RRF/CE），高差异 28 条口径 0.2857 → 0.2143；**危害口径（旧版页压过正确版）0.1935 → 0.0968，CE 降幅最大** —— 这是 CE 在本项目里唯一有实测收益的地方（slug 级指标把这份收益掩盖了）。[Z] 是独立集，**不与主集 Hit@5 混报**。

## 二、口径与环境（可复查）

- **命中判定**：检索结果的语料 slug（`metadata["source"]` 的文件名 stem）落在 `golden_slugs` 中即命中；一份文档拆多个 chunk，任一 chunk 命中即算该 golden 命中。
- **Hit@5**：top-5 内至少一个 golden slug 命中。**不可答类（40 条）无 golden，不计入 Hit@5**，单独统计拒答。分母 = **335** 条（asktug 148 + 文档事实 167 + 误杀探针 20 = 有 golden 的全部非不可答样本）。
- **可答/不可答三态**：无 chunk → `insufficient_evidence`；有 chunk 必调 LLM。本次只测检索与拒答判定，不涉及生成。
- **CE 子集**：从 335 条池子按 `source` 分层等比随机抽样 **200 条**，`seed=42` 固定；实际配额 asktug 88 / 文档事实 100 / 误杀探针 12。
- **拒答判定集**：40 条不可答 + 20 条误杀探针（误杀率必须在全量 20 条探针上统计，故一并送入 CE 打分）。CE 实际打分 **248 条**（200 子集 ∪ 60 判定集，去重后 248），比任务书写的 200 条多 48 条 —— 这是把"拒答误杀率 [A]→[B]"做出来所必需的，已在产物中留痕。
- **CE 候选**：`CE_CANDIDATE_K=30`、`CE_TOP_K=5`，沿用生产默认，未调。
- **冻结版本对齐（v0.1）**：本报告实测跑在 `data/eval_set.jsonl` 冻结 **v1.0** 上；随后并行会话发布了 **v0.1**（`data/eval_set_FROZEN.json`，`supersedes: 1.0`），修正两处主集 golden —— `mk_16`（`sql-statement-select-into` 磁盘不存在 → `sql-statement-select`）、`ask_3`（补 `dumpling-overview`，单证据升双证据），`ask_2` 仅加「松对齐」标注、golden 未动；31 条探针 `diff_point` 全部回填，并新增「高差异 28 条」第二口径（排除 ver_22/24/30）。
  **已离线按 v0.1 重判，结论：对 [X]/[Y] 与 Hit@20 零影响**（两条修正后仍未进 top-5 / top-20）；**仅 BM25 Hit@50 由 0.5552 变为 0.5582**（186→187 / 335，`mk_16` 的新 golden 落进了 BM25 top-50）。**对外 [X]/[Y] 一律以 v0.1 为准**，即 0.3045 / 0.3254（不变）。

## 四、拒答调优的方向被反转了（重要）

任务书假设：[A] 默认阈值误杀率高，调优让它"降下来"。
**实测是反的**：默认 0.3 下**误杀率本来就是 0**（从不拒答，自然零误杀），真正待优化的是**拒答能力**。因此：

- **[A] = 0.3（默认）**：拒答误杀率 **0.0（0/20）**、正确拒答率 **2.5%（1/40）** —— 等于拒答机制未生效。
- **[B] = 0.98**：拒答误杀率 **5%（1/20）**、正确拒答率 **25%（10/40）**、Hit@5 **不降**。这是在"命中率不降"约束下，把正确拒答率提升 **10 倍**的唯一膝点。
- 若 KPI 是"误杀率必须为 0"，则上限是 **0.95**（正确拒答率 15%、误杀 0）；到 0.97 仍保持误杀 0（正确拒答 17.5%）。
- 对外口径建议写成 **"拒答误杀率 0.0 → 5%（正确拒答率 2.5% → 25%）"**，并同时说明默认阈值下"零误杀"的成因，避免被追问时口径反转。

这一结果**在 TiDB 新语料上复现了 8 月的旧结论**：`CE_ANSWER_THRESHOLD` 之所以被废弃，就是因为 bge-reranker 的可答/不可答分数分布重叠。本次数据（可答 min 0.973 vs 不可答 p10 0.9443，重叠区极窄且不可分）**再次证伪**"用 CE 绝对分数做拒答门控"这条路。**真正的拒答机制应交给 LLM / validator 判定**，而不是 CE 分数阈值。

## 五、为什么 [Y]−[X] 只有 2.1 pt（失败模式初判）

对 RRF 档 226 条未命中样本做自动初判（判据：golden 是否出现在单路 top-50 内）：
- **召回缺失 114 条**（golden 在 BM25 与向量的 top-50 里都没有）
- **排序压制 112 条**（golden 进了候选池，但没排进 top-5）

按来源拆：AskTUG 92 召回缺失 + 42 排序压制；文档事实 18 召回缺失 + 65 排序压制；误杀探针 4 + 5。**多证据样本 26/27 全部未命中。**

两个结构性原因（**均为刻意保留的设计结果，不是 bug，不许改评测集**）：

1. **语料构成与 golden 目标错配**。语料 chunk 构成：社区类 72.2%（tidb-net 53,594 + asktug 21,607 = 75,190），官方类 27.8%（docs-cn 20,367 + 差异页 8,613 = 28,980）。而主集 golden **全部指向官方文档页**。实测 AskTUG 类 query 的 RRF top-5 结果里 **86% 来自社区语料**（asktug 帖 62% + tidb-net 专栏 24%），官方页只占 14%；文档事实类 query 稍好，官方类占 45%、社区类 54%。语料里社区内容多 2.6 倍、且排查类 query 的字面词天然更贴社区帖，官方页被系统性挤出。
2. **AskTUG 语料含题干原型帖**。AskTUG 类的 query 就是从社区帖改写的，其原帖本身在语料里（`asktug/*-topic.md`）且含完整报错原文，BM25 必然把它排到前面；而 golden 按设计指向**答案中引用的官方文档页**。命中原帖对真实用户是好事，但在本评测口径下算未命中。

**建议（W3/W4 讨论，未在本轮改动评测集）**：① 对 AskTUG 类补一条"原帖亦算命中"的辅助口径并单列报告，与主口径并存；② 主口径保留现状（golden 指官方页），把 AskTUG 低命中作为"术语鸿沟 + 语料原型泄漏"两类失败模式的实证样本，而不是调低它的权重。

**版本孪生干扰**（诊断项，不计入主集 Hit@5 惩罚）：top-5 命中的结果里落在**旧版差异页**（`docs-cn-v8.4/`）的数量 —— BM25 50 个、向量 40 个、RRF 47 个。同一 slug 在旧版页命中仍按命中计（slug 级口径），故版本混淆在本口径下**看不见** —— 必须靠独立探针集按 `metadata["source"]` 目录前缀判定，结果见第七节。

**标注落地情况**：上面这套自动初判（114 / 112）已被并行会话正式落进评测集 —— 定义与回填规则见 `data/failure_mode_spec.md`，`data/eval_set.jsonl` 的 `failure_mode` 字段已回填；术语鸿沟另做 50 条人工抽检（54% 存在，按来源极不均匀：AskTUG 80.0% / 文档事实 11.1%）。v0.1 把 `ask_3` 升为双证据后，**多证据样本总数由 27 变 28**（原文 26/27 未命中 即按旧总数计）。

## 七、版本混淆独立评测 [Z]（31 条探针，独立集，不与主集混报）

脚本 `scripts/eval_version_confusion.py`（复用 `eval_baseline_ladder` 的落盘/环境工具，未新增第二份实现）；命中判定按 `metadata["source"]` 目录前缀 —— `docs-cn/` = 正确版、`docs-cn-v8.4/` = 旧版页（twin）。31 条探针的 golden_slug 已核验**双版本页齐全 31/31**（含嵌套目录，如 `docs-cn/ticdc/ticdc-changefeed-config.md`）。索引未重建（`chunks=104192 collection=kb__tidb__bge-small-zh-v1.5__v2 count=104192` 逐位相符），耗时 **4.1 min**。

**[Z] 主口径 = top-5 内出现旧版页的探针占比**：
- BM25 **0.3226** / 向量 0.2581 / RRF **0.2581** / CE **0.2581**（全量 31 条）
- 高差异 28 条（排除 ver_22/24/30）：BM25 0.2857 / 向量 0.1786 / RRF 0.2500 / CE 0.2143

**正确版进 top-5**：BM25 0.3871 / 向量 0.3548 / RRF **0.4516** / CE 0.4194。
**危害口径（旧版页压过正确版，即用户真会看到错版本）**：BM25 0.1935 / RRF 0.1935 / 向量 0.1290 / **CE 0.0968**。
**top-1 是旧版**：BM25 0.1613 / RRF 0.1290 / 向量 0.0645 / CE 0.0645。**MRR(correct)**：CE 0.2941 最高。
head9（差异点精准）vs tail22（泛 query）的 [Z]：BM25 .4444/.2727、向量 .3333/.2273、RRF .3333/.2273、CE .2222/.2727；正确版进 top-5 的 head9/tail22：CE .6667/.3182。

**三条关键解读**：
1. **CE 的价值在版本口径上才显形**：slug 级主集里 CE 与 RRF 同为 0.31（净 0），但在版本正确性上 CE 把「旧版压过正确版」从 **19.4% 压到 9.7%** —— 因为 slug 级判定下新旧同名页都算命中，这份收益被指标掩盖了。
2. **RRF 是"正确版进 top-5"最高的一档（0.4516）**，但它的 [Z] 与 CE 同为 0.2581：新旧版常被**同时召回**（RRF 档 `any_golden_slug_in_top5 = 48.4%`，即 15/31 探针两个版本页都在 top-5 里），胜负全在排序。

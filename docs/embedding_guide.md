# Embedding 向量模型选型指南

## 为什么 Embedding 是 RAG 的基石

在 RAG 系统中，检索的精准度直接决定了最终回答的质量。而检索的核心在于如何将文本转化为计算机可以理解和比较的形式——这就是 Embedding（嵌入）模型的作用。

Embedding 模型将任意长度的文本映射为一个固定维度的稠密向量。语义相近的文本在向量空间中距离更近，语义相差甚远的文本则距离更远。这一特性使得基于向量相似度的语义检索成为可能。

---

## Dense vs Sparse Embedding

### Sparse Embedding（稀疏向量）

Sparse Embedding 是一种高维但极度稀疏的向量表示。通常维度与词表大小相当（如数万维），每个维度对应一个词，只有出现过的词才具有非零值。

**典型代表：BM25**

BM25（Best Matching 25）是一种经典的稀疏检索算法。它基于词频（TF）和逆文档频率（IDF）计算每个词对文档的相关性得分，本质上是一种带词长归一化的概率模型。

Sparse Embedding 的优势在于：

- 对精确关键词匹配非常有效（如品牌名、型号、技术术语）
- 可解释性强，能清楚看到是哪个词产生了匹配
- 计算效率高，适合大规模初步筛选

其局限性也很明显：无法捕捉语义相关性，"糖尿病"和"高血糖"这样的同义词在稀疏向量中毫无关联。

### Dense Embedding（稠密向量）

Dense Embedding 将文本映射为低维稠密向量（如 768 维、1024 维），每个维度都是经过神经网络学习得到的连续值，绝大部分维度都有非零值。

**典型代表：BERT、Sentence-BERT、BGE**

稠密向量的核心优势在于语义理解能力。"我爱吃苹果"和"Apples are delicious"在语义空间中距离很近，而 Sparse 向量可能完全不匹配。

其局限在于：

- 对精确术语匹配能力弱
- 训练成本高，需要大量标注数据
- 维度灾难在极高维度时仍需考虑

**实践中的共识**：现代 RAG 系统通常采用混合策略——先用 Sparse 或 Dense 做初步召回，再用更精准的模型做重排序。

## 主流模型对比

### BGE（BAAI General Embedding）

由北京人工智能研究院（BAAI）开发，是目前中文开源 Embedding 中表现最优秀的模型之一。

- **维度**：默认 1024（可压缩）
- **支持语言**：中英双语，中文效果尤佳
- **优势**：MTEB 榜单中文任务领先，开源可商用
- **适用场景**：中文知识库检索、跨语言检索

### m3-embed（Multimodal, Multilingual, Multi-hash）

Cohere 发布的最新一代嵌入模型，主打多模态与多语言统一表示。

- **维度**：1024
- **支持语言**：100+ 语言，中文原生支持
- **独特能力**：支持 BM25 稀疏向量与稠密向量同时输出，实现真正的混合检索
- **适用场景**：国际化产品、多语言知识库

### text-embedding-3（OpenAI）

OpenAI 发布的第三代嵌入模型，性能与灵活性兼顾。

- **维度**：1536（可维度缩减，能力几乎无损压缩至 256 维）
- **优势**：与 GPT 系列模型高度对齐，API 生态成熟
- **局限**：闭源商用有成本，非中文原生优化
- **适用场景**：快速集成 OpenAI 生态的产品

### 其他值得关注的选择

| 模型 | 维度 | 语言 | 特点 |
|------|------|------|------|
| GTE (BAAI) | 768/1024 | 中英 | 多任务统一表示 |
| Instructor (西湖大学) | 768-1792 | 多语言 | 支持指令引导 |
| Jina Embeddings | 1024 | 多语言 | 开源、中文友好 |

## 维度选择：更高是否更好

向量维度直接影响检索精度与存储/计算成本：

- **高维度（≥ 1024）**：表达能力更强，能容纳更丰富的信息，但存储成本高，相似度计算更慢
- **低维度（≤ 384）**：计算高效，但可能在语义区分度上有所损失

**维度缩减技术**：OpenAI 的 `text-embedding-3` 支持"能力保留缩减"——将 1536 维压缩到 256 维时，任务表现下降极小，同时节省约 6 倍的存储和计算资源。

**经验建议**：

- 中文语义检索优先选 BGE-1024
- 追求极致性价比可用 text-embedding-3 + 缩减至 256-512
- 对延迟敏感的场景选低维度模型

## 余弦相似度计算原理

在向量空间中找到最相似的文本，本质上是计算向量之间的距离。RAG 系统中最常用的度量是**余弦相似度（Cosine Similarity）**。

给定两个向量 **A** 和 **B**，余弦相似度定义为：

```
cosine(A, B) = (A · B) / (||A|| × ||B||)
```

即两个向量的点积除以各自模长的乘积。

**为什么是余弦相似度而不是欧氏距离？**

- 余弦相似度衡量的是**方向**的相似性，而非绝对距离。对文本长度变化更鲁棒——长文档和短文档只要语义相近，余弦值就高。
- 取值范围固定在 [-1, 1]，便于阈值设定。

**实际使用示例（Python）**：

```python
import numpy as np
from numpy.linalg import norm

def cosine_similarity(a: list[float], b: list[float]) -> float:
    a, b = np.array(a), np.array(b)
    return np.dot(a, b) / (norm(a) * norm(b))
```

主流向量数据库（如 ChromaDB、Milvus）内部自动计算余弦相似度，无需手动实现。

## 选型小结

| 维度 | 推荐模型 | 核心理由 |
|------|----------|----------|
| 中文场景 | BGE | 开源最强中文能力 |
| 多语言场景 | m3-embed | Cohere 原生多语言 |
| OpenAI 生态 | text-embedding-3 | 生态无缝集成 |
| 预算敏感 | GTE / Jina | 开源免费，效果尚可 |

选型没有绝对最优解，应根据**语言特性、精度要求、延迟需求和成本预算**综合考量。对于中文企业知识库，BGE 系列是当前最具性价比的选择。

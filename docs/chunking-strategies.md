# RAG 切片（Chunking）策略速览

> 切片策略的选择没有万能公式，需在**语义完整性、检索精度和上下文利用率**三者间权衡。

## 常见策略对比

| 策略 | 语义完整 | 实现难度 | 计算成本 | 适用内容 |
|------|----------|----------|----------|----------|
| 固定长度 | 低 | 极低 | 低 | 日志、网页 |
| 按句/段 | 高 | 低 | 中 | 博客、新闻 |
| 重叠切片 | 中高 | 低 | 中 | 论文、法律 |
| 语义切片 | 极高 | 高 | 高 | 手册、指南 |
| 代码 AST 分块 | 极高（代码语义） | 中 | 低 | Python 源码 |

## 代码 AST 分块（项目内已落地）

针对 Python 源码的专用策略：用 `ast.parse` 把源码解析成抽象语法树，按**函数 / 类 / 模块级语句**边界切分，避免通用滑窗把完整函数切成碎片。

- 每个 Chunk 对应一个完整语义单元（函数、类、方法）
- headings 自动带函数名/类名，检索时可直接命中
- 记录 `start_line` / `end_line`，便于定位源码
- 局限：仅适用 Python；超大函数/类需二次拆分；相邻 chunk 无重叠

mcp-rag-hub 具体实现见 [ast-chunking-plan.md](./ast-chunking-plan.md)。

## 实际建议

不要依赖单一策略。常见做法：

1. 先按语义或段落结构初步切分
2. 对每个片段计算 Token 数，过短向前合并，过长进一步拆分
3. 加入 10%~20% 重叠，减少边界丢失
4. 切片策略与检索评估联动：定期分析低相关性案例，针对性调优
